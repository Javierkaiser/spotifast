What to look at

  • Storage section: the new Cache folder row. Before, the section starts at Artwork cache, and nothing there says where the caches live.
  • Cache sizes: the Audio cache row in Playback on this computer. Before: 512 MB, 1 GB and 4 GB on one line. After: 256 MB, 512 MB, 1 GB, 2 GB, 4 GB, 8 GB and 16 GB, which wraps onto three lines at this width.
  • Already chosen: both sides are given the same stored preference, a folder named in the demo settings file. Before, it is ignored, the rows show the default cache folder and there is no control to change it. After, the row shows the chosen folder with Use default and Change folder, and the artwork and audio cache rows point inside it.
  • Whole page: everything above at once, at two window widths, which is also where the rest of the page can be checked for damage.

Remaining checks

  • The picker dialog itself is not in these captures. A native dialog cannot be opened in the headless setup they were made in, so the row appears in its resting state.
  • A folder chosen inside a Flatpak sandbox is not verified here. The picker goes through the desktop portal, so the stored path is a portal one, and whether it survives a restart is a portal property. What the application does when the stored folder is not usable at start is the documented fallback.
  • No macOS or Windows captures, and no recording of the picker being used.
